# Separate transport and business status

Foundry HTTP APIs use HTTP status codes for transport and protocol failures: request validation returns 400, unmatched routes return 404, and unhandled server errors return 500. Their response bodies are not a stable application contract, so clients branch on the HTTP status alone. Requests that reach business logic return HTTP 200 for both successful and handled unsuccessful outcomes; clients distinguish those outcomes through the JSON response envelope's internal `status`. Every HTTP 200 envelope contains `status` and `data`, using `data: null` when no result exists, while `message` may provide displayable feedback. This keeps infrastructure failures observable through standard HTTP semantics while preserving a uniform application-level contract.
