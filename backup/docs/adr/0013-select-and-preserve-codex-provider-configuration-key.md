# Select and preserve the Codex Provider configuration key

Foundry derives the Codex Provider configuration key from the `[model_providers.<key>]` tables in `~/.codex/config.toml` instead of storing it in the database. The top-level `model_provider` value does not influence key selection: Foundry creates and uses `foundry` when no Provider table exists, automatically reuses the sole existing key, and asks the user to choose in the configuration Preview when multiple keys exist. The selected key becomes the proposed top-level `model_provider` value, so that field appears among changed or unchanged Preview fields according to its current value. Applying a different saved Provider updates only the Foundry-owned fields under the chosen table, while unrelated fields and every other Provider table are preserved; Official Default removes the active top-level selection but retains all Provider tables. A per-Provider generated key and a database-persisted key were rejected because changing keys can fragment Codex session discovery, while file-based selection keeps the choice visible and under user control.
