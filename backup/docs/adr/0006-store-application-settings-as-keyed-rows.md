# Store Application Settings as keyed rows

Application Settings are stored in a `settings` table with one row per setting, using a unique registered `key`, a JSON-encoded `value`, and the standard Foundry identity and timestamp fields. The migration that introduces a setting also inserts its default row; missing or unknown setting keys are treated as invalid database state rather than ignored or repaired at runtime. This row-oriented model favors a uniform, extensible settings table over database-level types for individual settings, so the server validates each value against the schema registered for its key. Settings APIs expose only the typed logical settings object rather than storage rows or metadata, and every accepted update refreshes `updated_at` even when the submitted value equals the stored value, making it the last successful write time.
