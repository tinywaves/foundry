# Use a module-oriented Foundry Export package

Foundry exports all Exportable Data as one ZIP-backed `.foundry` file with the top-level format identifier `foundry-export-v1`; its manifest records the creation time, Foundry version, and each module's identifier, path, media type, `overwrite` policy, byte size, and SHA-256 checksum. Each Export Module owns its payload encoding, with Application Settings and active Providers initially encoded as JSON and incompatible changes represented by a new top-level format rather than per-module schema versions. Provider payloads contain the complete data needed to create a Provider, including API keys, but omit database identifiers, timestamps, and deletion metadata; Runtime Assignment and other machine-specific operational state are excluded. Export succeeds or fails as a whole. Import validates the package before processing known modules atomically and independently: Application Settings are replaced, Providers are appended with new database-owned fields, and unsupported or failed modules are reported without rolling back successful modules. The binary container discourages direct editing but does not provide encryption or a guarantee against deliberate modification.
