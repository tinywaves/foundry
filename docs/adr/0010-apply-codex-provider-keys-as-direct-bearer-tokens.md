# Apply Codex Provider keys as direct bearer tokens

When a Codex Provider contains a static API key, Foundry applies it through Codex's `experimental_bearer_token` configuration instead of requiring the user to maintain an external environment variable. Codex currently discourages this field in favor of `env_key`, but Foundry manages configuration files rather than launching Codex processes and therefore cannot reliably inject a stored secret at process startup; accepting the direct token keeps a saved Provider self-contained and immediately applicable. The key consequently exists in both `foundry.sqlite` and the generated Codex configuration, consistent with the local security boundary recorded in ADR 0008, and this integration must be revisited if Codex removes the field.
